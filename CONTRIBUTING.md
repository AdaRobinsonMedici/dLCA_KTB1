# Contributing

The project separates the general dLCA framework from the KTB1 demonstration. State which layer a proposed change affects.

## Report a problem

Use the bug-report template with the repository commit, notebook/cell, environment and a minimal example. Include units and time conventions when relevant. Remove credentials, local usernames and restricted data from logs before posting publicly.

## Propose a change

1. Work on a branch and keep the change focused.
2. Describe effects on inventories, units, time alignment, datasets, LCIA method selection or scheduling results.
3. Preserve third-party attribution and the existing licence.
4. Clear notebook outputs and execution counts before committing.
5. Run the repository checks documented in the [README](README.md).
6. For scientific changes, provide permitted input provenance and before/after results from the confirmed research environment.

Passing repository checks is not evidence that a scientific change is correct. Avoid adding a numerical claim without reproducible evidence.

Do not post confidential inventions, unpublished control designs, passwords or licensed database dumps in issues, branches or pull requests. These are public in this repository.
